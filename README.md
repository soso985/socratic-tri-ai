# 三 AI 自主项目开发系统

**Socratic Mentor · Autonomous Executor · Independent Controller**

一套以「用户 / 指导老师 AI / 执行工程师 AI / 调度监管 AI + 确定性控制程序」为骨架的
AI 自主项目开发治理体系设计基线。

设计重点不是增加 AI 数量，而是实现**可追溯需求、明确权责、受控变更、真实成果验证、
复杂问题的分层交互和长期自主恢复**。系统不得以多个 AI 意见一致代替客观验证，
也不得以自动化为理由越过用户授权。

## V1.4 相对 V1.3 补入了什么

1. **技术异议通道**（§8.4）— 执行者有异议权、无更改权；无法执行必须先提异议，任务立即 BLOCKED。
2. **重大性判定与升级**（§8.5）— Mentor 与 Controller 依**同一张 7 条清单**、用**不同模型**、**互不可见**地各判一次；分歧交 Owner 裁决。
3. **异议强制留痕**（§8.6）— 异议提交即由程序自动登记，并在 §9 验收与 §13 集成时显式复核一次。
4. **Controller 权限边界**（§2.3）— 阻断权来自证据与流程，**不判技术**；开工前只核对方案完整性。
5. **等待期默认暂停**（§6.5）— 凡等待用户决策期间，默认暂停，**绝不自动放行、绝不降级为单方决策**。
6. **Mentor 对 Owner 的反对与留档**（§6.6）— 反对是义务；用户坚持则必须服从，但全程留档并在 §13 复核。

## 三条铁律

| # | 铁律 | 条款 |
| --- | --- | --- |
| 1 | **有异议权，无更改权** — 执行者能喊停，不能自己改 | §8.4 |
| 2 | **各判一次，互不可见，分歧到你** — 两个不同模型各判一次，判不一样就交用户 | §8.5 |
| 3 | **等待期间默认暂停** — 没有任何路径允许「等太久就先放行」 | §6.5、§10.2-37 |

## 已知缺口（明示，不假装已覆盖）

按 §1.3-7「未验证必须明确标为未验证」的精神登记，详见 V1.4 附录 G：

| 编号 | 缺口 |
| --- | --- |
| **G-1** | 技术路线**没有事前把关人**，靠 §13 必答项与 P1/P5 阶段验收事后暴露 |
| **G-2 / G-5** | **不产生流程后果**的纯技术异议，双方通常同判「不重大」，异议就地封闭（留痕但不阻断） |
| **G-3** | 需求层偏差无阻传播——§4 澄清与 §5 审计是需求质量的唯一闸门 |
| **G-4** | 任一模型 API 不可用时的策略未定（暂由 §6.5 通则兜底为暂停） |
| **G-6** | 风险登记不进入升级判定（**已在 V1.4 补条款修复**） |
| **G-7** | 对「有害需求」**没有硬阻断**，只有书面反对 + 归档 + 事后复核 |

**回补路径**：G-2 与 G-5 若要补，方式不是重新设计，而是引入**对抗性评审（红队）**——
代价是要同步修订 §2 的角色边界。
